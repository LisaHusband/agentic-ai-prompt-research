# Compact 服务（对话摘要）

**观察自**：Claude Code 内部架构
**变量：** `NO_TOOLS_PREAMBLE`、`BASE_COMPACT_PROMPT`、`PARTIAL_COMPACT_PROMPT`、`PARTIAL_COMPACT_UP_TO_PROMPT`
**模型：** Sonnet（通过共享缓存的 fork 或流式降级路径）

## 用途

当上下文窗口接近其上限时，生成详细的对话摘要。compact 服务有三种运行模式：完整压缩、对最近消息的部分压缩，以及对较旧消息的部分压缩。

## No-Tools 前言

作为第一条指令注入，以防止模型在摘要期间调用工具。这一点至关重要，因为共享缓存的 fork 路径会继承父级的完整工具集。

```
关键：只以纯文本回复。不要调用任何工具。

- 不要使用 Read、Bash、Grep、Glob、Edit、Write 或任何其他工具。
- 你在上面的对话中已经拥有你需要的全部上下文。
- 工具调用会被拒绝，并会浪费你唯一的一次回合——你将会任务失败。
- 你的整个回复必须是纯文本：一个 <analysis> 块，后面跟一个 <summary> 块。
```

## Base Compact 提示词（完整摘要）

在整个对话被摘要时使用：

```
你的任务是创建一份到目前为止对话的详细摘要，密切
关注用户的明确请求以及你此前的动作。
这份摘要应当详尽地捕获技术细节、代码模式和
架构决策，这些对于在继续开发工作时
不丢失上下文而言是必不可少的。
```

### 必需的摘要小节

1. **主要请求与意图**——所有明确的用户请求和意图
2. **关键技术概念**——讨论过的技术、框架、模式
3. **文件与代码段落**——检查过/修改过/创建过的文件及完整代码片段
4. **错误与修复**——遇到的错误及解决步骤
5. **问题解决**——已解决的问题和正在进行中的排查
6. **所有用户消息**——每一条非工具结果的用户消息（对于追踪意图漂移至关重要）
7. **待办任务**——未完成的工作项
8. **当前工作**——在摘要之前正在进行的工作的精确描述
9. **可选的下一步**——只有当与最近的用户请求直接一致时才给出下一步

## Partial Compact 提示词（最近的消息）

当只对最近的消息做摘要、而较旧的上下文被保留时使用：

```
你的任务是创建一份对话中最近部分的详细摘要——
即更早那份被保留的上下文之后的消息。更早的消息被原样
保留，不需要被摘要。把你的摘要聚焦于仅在这些最近消息中
讨论、学到和完成的内容。
```

## Partial Compact Up-To 提示词（较旧的上下文）

在对较旧的消息做摘要以腾出空间、而较新的消息被原样保留时使用：

```
你的任务是创建这份对话的详细摘要。这份摘要将会被
放在一个继续进行的会话开头；在这份摘要之后会跟随
建立在此上下文之上的较新消息（你在这里看不到它们）。请详尽地摘要，
以便只读你的摘要、然后读较新消息的人能够完全理解
发生了什么并继续这项工作。
```

它会用“Work Completed”替换第 8 节（“Current Work”），并用“Context for Continuing Work”替换第 9 节。

## Analysis 块

所有三个变体都包含一条 `DETAILED_ANALYSIS_INSTRUCTION`，要求模型在 `<summary>` 之前先把推理包在 `<analysis>` 标签中。analysis 块是一块草稿暂存区，会在摘要进入上下文之前被 `formatCompactSummary()` 剥除。

```
在给出你的最终摘要之前，把你的分析包在 <analysis> 标签中，
以整理你的思路并确保你已经覆盖了所有必要的要点。在你的分析过程中：

1. 按时间顺序分析对话的每一条消息和每个部分。对每个
   部分，彻底识别：
   - 用户的明确请求和意图
   - 你处理用户请求的方式
   - 关键决策、技术概念和代码模式
   - 具体细节，如：文件名、完整代码片段、函数签名、文件编辑
   - 你遇到的错误以及如何修复它们
   - 特别注意具体的用户反馈
2. 复核技术准确性与完整性。
```

## 自定义指令支持

compact 提示词支持通过 CLAUDE.md 或 hooks 提供的用户摘要指令：

```
在包含的上下文中可能提供了额外的摘要指令。
如果有，请记住在创建上述摘要时遵循这些指令。
```

## 架构说明

- **共享缓存的 fork**：一个继承父级提示词缓存的 fork 进程。它需要 `NO_TOOLS_PREAMBLE`，因为它同时也继承了完整的工具集。
- **流式降级**：如果 fork 路径失败（例如模型在 `maxTurns: 1` 下尝试工具调用），则降级到标准的流式查询。
- **主动模式集成**：当主动模式或 Kairos 被启用时，会追加关于主动任务的额外上下文。
