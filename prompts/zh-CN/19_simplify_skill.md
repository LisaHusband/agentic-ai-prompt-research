# Simplify 技能

> **类型**：内置技能（bundled skill，编译进 Claude Code 二进制）
>
> **调用方式**：`/simplify` 或 `/simplify focus on [area]`
>
> `/simplify` 命令是一个内置技能，它会对最近改动的文件执行一次自动化的、多 agent 的代码评审与清理。它被设计为在实现某个功能或修复某个 bug 之后、打开 pull request 之前运行。

## 可用性

这是一个**内置技能**，意味着它随 Claude Code 二进制一起发布，无需安装。与放在 `.claude/skills/` 中的自定义技能不同，该技能由 Anthropic 维护，并随 Claude Code 的版本发布一起更新。确切的 `SKILL.md` 源码被编译进二进制中，无法公开获取。

以下文档是根据公开文档、社区来源和行为分析重建的。

## 工作流

### 阶段 1：变更检测

该技能通过检查最近的变更来确定评审范围：

- 如果位于 Git 仓库内，运行 `git diff`（或对已暂存的变更运行 `git diff HEAD`）以确定哪些内容被修改
- 如果未检测到 Git 仓库，则评审最近修改过的文件
- diff 输出定义了评审的确切范围

### 阶段 2：三 agent 并行评审

三个专门的子代理被并行生成，每个都收到完整 diff 作为背景：

#### 代码复用 agent

评审变更以识别：

- 可被抽取为共享函数的重复逻辑
- 应当被使用、而不是写新代码的既有工具函数或 helper
- 冗余的代码块和重复的模式
- 重构为可复用组件或模块的机会

#### 代码质量 agent

评估代码结构与风格：

- 命名一致性与可读性
- 函数拆分与控制流清晰度
- 是否符合 `CLAUDE.md` 中定义的编码标准
- 代码坏味道，如抽象泄漏、字符串化类型（stringly-typed code）、不必要的嵌套
- 过度工程、不必要的抽象或过早优化（“镀金”）

#### 效率 agent

分析性能与资源使用：

- 不必要的分配和冗余计算
- 可被批处理或优化的循环
- N+1 查询模式，以及低效的文件或网络访问
- 被浪费掉的并发机会
- 不必要的重复渲染（在前端代码中）

### 阶段 3：汇总与修复应用

一旦三个 agent 都完成评审：

1. 各项发现被汇总并去重
2. 误报或不值得处理的发现被跳过
3. 修复被直接应用到代码库
4. 向用户报告改动内容的摘要

## 用法

```
/simplify                              # 评审所有最近的变更
/simplify focus on memory efficiency   # 聚焦于特定关注点
/simplify focus on performance         # 针对性能问题
```

## 与 CLAUDE.md 的集成

`/simplify` 的有效性在很大程度上取决于项目的 `CLAUDE.md` 文件。质量 agent 使用其中定义的编码标准和偏好，使其建议与团队的约定保持一致。拥有定义良好的 `CLAUDE.md` 文件的项目会得到明显更好的结果。

## 设计特征

| 属性 | 细节 |
|----------|--------|
| **Agent 数量** | 3 个并行子代理 |
| **范围** | 仅最近的变更（通过 `git diff`） |
| **执行** | 各 agent 并行运行以提高效率 |
| **修复模式** | 自动应用并给出摘要 |
| **误报** | 跳过而不是争辩 |
| **可定制** | 接受关注领域作为参数 |
| **依赖** | 读取 `CLAUDE.md` 以获取项目专属标准 |

## 在工作流中的位置

推荐的工作流是：

```
构建功能 → 运行测试 → /simplify → 评审 diff → 提交
```

这把 `/simplify` 定位为一次实现后的清理，用来收紧 AI 生成的代码（后者倾向于冗长）。它不是人类代码评审的替代品，而是把机械性的清理部分自动化了。

## 相关命令

| 命令 | 关系 |
|---------|-------------|
| `/init` | 搭建 `/simplify` 用来读取标准的 `CLAUDE.md` |
| `/diff` | 在运行 `/simplify` 之前预览变更 |
| `/batch` | 用于跨整个代码库的大规模重构（作为 `/simplify` 的替代品，后者只针对最近的变更） |
